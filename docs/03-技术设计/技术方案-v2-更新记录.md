# 技术方案 v2 更新记录

## 版本结论
v2 采用“赛题参考版”策略，不做严格参赛交付版。技术方案从“学生学习路径推荐平台”调整为“岗位能力图谱构建与人岗匹配诊断系统”。

## v1问题
1. 项目定位偏学生职业规划。
2. 学习路径推荐过重，岗位能力图谱不够突出。
3. 与赛题中的新岗位发现、既有岗位能力动态更新、简历解析要求存在错位。
4. 与招聘平台差异没有说清楚。
5. MVP 边界容易继续扩张。

## v2调整
1. 项目定位改为：面向计算机类学生的岗位能力图谱构建与人岗匹配诊断系统。
2. 主链路改为：岗位 JD 导入 → 技能抽取 → 岗位能力图谱 → 学生能力录入 → 人岗匹配 → 能力缺口 → 学习路径建议。
3. 学生成长报告降级为“人岗匹配诊断报告”。
4. 新岗位发现、既有岗位能力动态更新在第一版作为演示样例和扩展能力，不作为 MVP 硬开发项。
5. 新增竞品差异分析，明确不替代 BOSS 直聘，而是招聘平台前置能力诊断工具。
6. 第一轮数据要求从 100 条 JD 调整为 10 条 JD 样例，后续按验证结果扩充。

## 保留内容
1. 网站产品形态。
2. Vue3 + Vite + Element Plus + ECharts 前端路线。
3. Spring Boot + MySQL 后端主线。
4. Python 数据处理能力。
5. 国内开放云端 API 优先策略。
6. 规则匹配优先、AI 文本生成补充的原则。

## 降级内容
1. 学生画像：保留为能力录入表单。
2. 项目库：保留为项目经历录入，不做复杂管理。
3. 成长报告：改为诊断报告。
4. 简历解析：第一版用结构化表单模拟，后续再做 PDF/Word。
5. 动态演化：第一版用批次样例模拟，后续再做真实时间窗口对比。

## 新增内容
1. 竞品差异章节。
2. 岗位 JD 样例模板。
3. 技能证据句字段。
4. 能力缺口证据说明。
5. AI 输出兜底策略。
6. 版本更新记录。
