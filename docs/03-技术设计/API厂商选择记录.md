# API厂商选择记录

## 选择原则
1. 优先开放云端 API；
2. 优先国内 API；
3. 尽量使用同一个厂商；
4. API 不绑定核心决策；
5. 必须保留规则兜底。

## 候选厂商
### 讯飞星火
优势：与赛题发榜单位方向接近，适合中文文本理解、报告生成。  
风险：接口申请、额度、费用需要确认。

### 通义千问
优势：文档多、生态成熟、中文能力稳定。  
风险：与赛题发榜单位关联较弱。

### 豆包
优势：你当前工具环境可能更熟悉。  
风险：项目技术文档需要明确调用边界。

## MVP 建议
先统一选择一个厂商作为主 API。  
若你后续想贴合赛题背景，优先调研讯飞星火 API；若为了开发便利，可以先用豆包或通义千问。
